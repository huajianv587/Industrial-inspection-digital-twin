# Codex 主任务书：工业四足机器人端到端巡检系统

你是负责交付可验证工程的机器人软件架构师。请在当前仓库基础上逐阶段开发，不要把未运行的代码、模拟数据或静态接口描述成已完成系统。

## 项目目标
构建基于 NVIDIA Isaac Sim 与 Unitree Go2（或在资产可用时 B2）的工厂巡检系统。业务闭环为：站点配置 → 航点导航 → 多模态采集 → 感知 → 异常判断 → 人工复核型工单 → 报告/数据库。第一阶段只在仿真中进行；当前离线基线必须继续可运行。

## 必须遵守
1. 开始前阅读 `README.md`、`docs/ARCHITECTURE.md`、`docs/DATA_CONTRACT.md`、`docs/CODEX_HANDOFF.md`。
2. 按 `docs/CODEX_HANDOFF.md` 的 Phase 0–6 顺序推进，不要一次性重写项目。
3. 每阶段先给出目标、假设、涉及文件、依赖、验收命令和风险，再编码。
4. 对 Isaac Sim/ROS 2/Unitree SDK 使用可核对 API。先确认目标版本，遇到版本差异做兼容层，不要凭空假设 API。
5. 不可伪造真机测试、合成图像数量、模型准确率、热测温度精度或现场部署成果。
6. 观测需保留来源、时间戳、机器人 ID、航点 ID、设备 ID、模型/校准版本和质量标记。
7. 缺失测量必须保持 `null`/UNKNOWN，不得静默当作正常。
8. 处置建议默认需人工复核；不允许模型自动执行泄压、停机、开关柜或阀门动作。
9. 新增代码须有类型提示、日志、异常处理、单元测试和简明文档。
10. 每阶段结束运行测试，报告命令、环境、通过/失败项和未验证项。

## 首个任务
检查仓库并运行离线测试和 CLI；修复实际发现的问题并添加回归测试。不要跳过基线直接生成大型 Isaac Sim 实现。基线稳定后，再按 Phase 1 开始。

## 每阶段汇报格式
- 本阶段目标
- 实际修改文件
- 实现细节
- 执行过的命令与真实结果
- 未完成/未验证项
- 下一阶段计划

不要把计划写成已完成，不要只输出架构建议；需要在仓库中实际修改代码。
