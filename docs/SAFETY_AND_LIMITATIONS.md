# 安全边界与限制

1. **当前仓库不控制真机。** `RobotAdapter` 是可替换的结构化接口；当前 `SimulatedRobotAdapter` 仅记录模拟导航事件，不发送 ROS 2 消息，也不连接 Unitree SDK。编排器会核对 adapter 声明来源与航点观测身份。
2. **模拟值不是真实传感器读数。** 所有示例值均带 `synthetic_simulation` 来源标记。
3. **工单不应自动触发危险操作。** 不自动泄压、停机、开关柜或操作阀门；涉及现场动作必须由授权人员按规程确认。EAM 提交只有在人工 `ACKNOWLEDGED` 后才允许，由 `admin` 显式触发；当前只实现受审计、可重试的 adapter 边界，没有经过厂商端点、凭据、审批和外部回放验收。
4. **红外测温需要校准。** 需处理发射率、反射温度、距离、大气传输、视场和传感器自身误差。
5. **泄漏检测只是疑似异常。** 视觉模型无法单独证明存在真实介质泄漏，需结合独立证据与现场复核。
6. **导航和运动控制要分层。** Nav2 负责高层导航任务，不等同于四足步态控制器；机器人专用接口、急停、限速和故障安全需单独设计。
7. **现场部署需做风险评估。** 包括人员/机器人共域、危险区域防爆要求、网络安全、权限、日志、失联处置和人工接管。
8. **不要虚构性能指标。** 仅报告已运行的测试和可复现结果；对未完成模块明确写“待实现”。
9. **数据库与账号隔离。** 生产环境只允许连接 Supabase PostgreSQL；迁移 owner URL 与应用运行 URL 必须分离。业务表启用 RLS，运行角色无建表、删除或审计更新权限。未核对项目 ref 前不要运行迁移。
10. **外部凭据。** SSH 密码曾在聊天中明文暴露，不得复用；先轮换，再配置独立 SSH key 和固定 host key。Supabase 密码、anon key 以外的服务密钥不得提交或写入浏览器。
